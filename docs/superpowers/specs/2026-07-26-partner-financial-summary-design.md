# 合作单位财务概览设计

## 目标

压缩合作单位页面左侧概览宽度，在右侧主档表格直接显示每个合作单位的收款、开票和付款关键金额，使授权用户无需进入详情页即可完成快速比较。

## 范围

- 桌面端左侧概览调整为约 220px 的紧凑固定列，右侧占用剩余宽度。
- 900px 以下继续使用上下排列，不压缩移动端内容。
- 右侧表格新增“收款”“开票”“付款”三个独立列。
- “财务”操作继续跳转现有合作单位详情页，不改变既有页面地址和录入流程。
- 不修改数据库结构，不复制或重算中央账本之外的财务口径。

## 财务口径

财务数据只使用外部中央账本中的有效记录，并按合作单位、应收/应付方向分别汇总：

- 收款列：应收方向的 `CashAmount` 显示为“已收”，`UncollectedOrUnpaid` 显示为“未收”。
- 开票列：应收方向的 `InvoicedAmount` 显示为“销项”，应付方向的 `InvoicedAmount` 显示为“进项”。
- 付款列：应付方向的 `CashAmount` 显示为“已付”，`UncollectedOrUnpaid` 显示为“未付”。
- 无账本记录时显示 `0.00`，金额统一使用千分位和两位小数。

## 权限

财务列仅向系统管理员、应用管理员、财务和查询角色显示。项目经理、现场人员等其他角色继续看到现有非财务主档列，避免扩大财务数据可见范围。现有编辑、复制和财务操作权限保持不变。

## 数据流与性能

在中央账本查询服务增加批量合作单位汇总接口，输入当前页面涉及的合作单位 ID，一次读取授权范围内的相关结算及分摊数据，并按合作单位和方向生成汇总结果。页面模型只负责把汇总结果映射到列表行。

批量接口复用 `CentralLedgerCalculator` 和现有授权范围，不在 Razor 页面直接访问财务表，也不对每一行分别调用 `GetPartnerMetricsAsync`，从而避免 N+1 查询。

## 页面排版

授权用户的表格列为：单位、角色/专业、联系人、项目、收款、开票、付款、状态、操作。每个财务单元格固定两行标签和值，金额右对齐并使用稳定宽度，操作按钮继续单行显示。长单位名称和备注仍按现有省略规则处理。

非财务角色不渲染三个财务列，空状态行的 `colspan` 随权限动态变化。列管理预设同步包含财务列，但不会向无权限角色输出对应数据。

## 错误处理

中央账本查询失败时让页面请求失败并记录现有服务异常，不把错误伪装成零金额。无记录与查询失败必须保持可区分。

## 验证

- 服务测试：验证同一合作单位的应收和应付指标分开汇总，其他合作单位不会串账，旧单个合作单位指标接口保持不变。
- 页面模型测试：验证授权角色获得财务汇总，非授权角色不调用财务服务。
- 页面契约测试：验证三个财务列、动态 `colspan`、紧凑左栏和单行操作存在。
- 回归测试：运行合作单位、中央账本、权限和响应式测试，并执行完整测试集与 Release 构建。
- 手动验收：桌面检查金额对齐与左右宽度，390x844 检查上下布局和表格自身横向滚动。
