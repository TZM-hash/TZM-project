# 工资台账工作台与中央账本自动并入设计

**日期：** 2026-07-28  
**状态：** 用户已确认方案，待实施

## 1. 目标

将工资台账改造成与施工班组页面一致的桌面端单页工作台：汇总、筛选、列表、查看、新建和编辑集中在同一页面。所有工资仍只从工资台账录入；形成真实账户流出的有效工资批次自动出现在中央账本，不要求二次录入，也不复制资金流水。

## 2. 范围与边界

- 改造 `/Payroll/Index` 的显示层级、筛选、列表和弹窗操作。
- 将新建、查看、编辑工资批次纳入工资台账页面弹窗。
- 保留 `/Payroll/Edit` 作为兼容入口，并将既有深链参数转到工资台账对应弹窗。
- 扩展中央账本查询结果和外部账本页面，使有效工资批次显示为只读工资付款。
- 保留现有工资校验、权限、并发控制、历史人员回显、账户流水和审计行为。
- 不修改数据库结构，不新增工资副本，不改变工资领域规则或现有保存服务契约。
- 本轮只做桌面端验证，不做手机端验证。

## 3. 工资台账工作台

### 3.1 页面结构

页面采用施工班组工作台的结构和视觉语言：

- 紧凑页面标题与右侧主操作按钮。
- 左侧概览栏显示批次数、实际发放总额、员工发放、班组发放，并提供状态快捷筛选。
- 右侧为集成工具栏和数据表格，继续使用现有 DataWorkbench 搜索与列配置。
- 表格单元格采用主信息、次信息和状态标签的分层展示，操作列使用与施工班组一致的操作按钮组。

列表保留批次编号、名称、发放日期、人数、实际总额、员工金额、班组金额、差额和状态等现有业务信息。状态筛选作用于右侧列表；左侧汇总使用当前搜索范围的全量结果，避免因状态切换丢失整体判断。

### 3.2 查看弹窗

查看操作打开只读桌面窗口，展示：

- 批次编号、名称、发放日期、发放类型和状态。
- 项目、发放公司、资金来源、账户、支付方式和凭证号。
- 员工人数、班组人数、员工金额、班组金额、实际总额和差额。
- 当前批次人员明细和备注。

只读角色沿用现有权限边界，不因页面合并获得工资管理权限或额外敏感信息。

### 3.3 新建与编辑弹窗

编辑弹窗使用施工班组同款窗口标题、关闭方式、分区布局和底部操作区。内容分为：

1. 批次资料。
2. 付款信息。
3. 人员明细。
4. 核对结果。

人员明细使用“自有员工”和“施工班组人员”标签切换，避免两个长表同时展开。核对结果和保存操作固定在弹窗底部，实时显示人员明细合计、实际发放总额和批次差额。

保存失败时保留用户输入和验证信息，并自动重新打开编辑弹窗。并发冲突、人员状态、班组归属、账户与公司关系等校验继续由现有服务执行。

### 3.4 兼容入口

`/Payroll/Edit` 不再承担独立编辑界面，但继续接受 `id`、`lineId` 和 `returnUrl`。进入该地址时转到 `/Payroll/Index`：

- 有 `id` 时打开对应批次查看或编辑弹窗。
- 有 `lineId` 时切换到正确人员标签并高亮对应明细。
- `returnUrl` 继续用于保存后返回原业务页面。

## 4. 中央账本自动并入

### 4.1 数据来源

中央账本直接查询统一工资批次和工资保存时已经生成的 `AccountTransaction`。不额外创建 `FinanceCashEntry`，避免同一笔资金支出出现两份可编辑记录或重复影响账户余额。

只有以下状态进入中央账本：

- 已核对（`Confirmed`）
- 已关闭（`Closed`）
- 修改待复核（`ModifiedPendingReview`）

草稿和作废批次不进入工资付款结果。有效批次回退草稿时，中央账本不再展示原付款；重新生效后自动恢复展示。既有冲销流水继续由工资服务维护。

### 4.2 中央账本展示

外部中央账本的付款区域新增只读“工资付款”记录，字段包括：

- 发放日期。
- 批次编号与名称。
- 发放公司、项目和付款账户。
- 员工金额、班组金额和实际发放总额。
- 工资批次状态。
- 返回工资台账的查看操作。

中央账本查询结果增加独立的工资付款集合和工资付款总额。工资付款总额不直接并入结算指标中的“已付”，因为自有员工工资没有合作单位结算对象；班组工资也不得在已有结算资金中重复统计。

### 4.3 筛选与权限

工资付款遵守中央账本现有的：

- 自有公司授权范围。
- 项目授权范围。
- 财务年度和自定义日期区间。
- 公司、项目和关键词筛选。
- 外部账本读取权限。

关键词覆盖批次编号、批次名称、项目、公司、账户、凭证号和备注。中央账本仅提供只读来源跳转，所有修改继续在工资台账完成。

## 5. 数据流与错误处理

工资保存流程保持事务边界不变：工资批次、人员明细、班组关联、账户流水、个人垫付影响和审计记录继续一次提交。中央账本查询不参与工资保存事务，只在读取时投影有效工资，因此不会出现“工资已保存但中央账本副本同步失败”的中间状态。

中央账本工资查询必须忽略缺少有效账户流水的异常批次，并通过测试暴露该数据不一致；页面不得猜测或生成替代流水。来源批次不存在或用户无权查看时，返回明确的未找到或无权限结果。

## 6. 测试与验收

### 6.1 自动化测试

- 工资台账页面具备施工班组式工作台结构、弹窗和操作入口。
- 新建、编辑、验证失败、并发冲突和历史停用人员往返行为保持正确。
- `/Payroll/Edit` 深链正确转到工资台账弹窗并保留 `lineId` 与 `returnUrl`。
- 有效工资批次出现在中央账本工资付款结果，草稿和作废批次不出现。
- 批次修改、状态回退和重新生效后查询结果同步变化。
- 中央账本公司、项目、日期、年度、关键词和授权筛选适用于工资付款。
- 工资付款只引用既有账户流水，不新增或重复账户流水。
- 中央账本工资付款总额与有效批次实际发放总额一致，且不重复并入结算“已付”。

### 6.2 桌面端验证

- 工资台账概览、列表、筛选和操作按钮布局与施工班组工作台一致。
- 新建、查看、编辑弹窗可正常打开、关闭、切换人员标签和提交。
- 金额合计和差额实时更新，验证错误不会关闭或清空弹窗。
- 中央账本可以看到工资付款，并可返回对应工资批次。
- 检查桌面视口下的溢出、遮挡、控制台错误和关键网络请求。

不执行手机端布局或交互验证。
