# 中央账本外部与内部账本工作台设计

## 1. 设计目标与范围

中央账本是项目、合作商、施工班组、工资台账、公司账户、发票、对账和财务年度共用的财务事实层。本次目标是重做中央账本的呈现与操作层，使外部账本、内部账本在视觉结构、按钮、弹窗、筛选、表格、金额颜色和右侧工作区方面与员工管理、工资台账一致，同时不复制任何财务金额，也不改变现有权限隔离和业务计算口径。

范围包括：

1. 外部账本与内部账本首页工作台。
2. 真实业务标签和各标签的数据列表。
3. 统一新增/编辑弹窗和类型化字段联动。
4. 统一详情弹窗、来源跳转、关联分摊和修改记录展示。
5. 待分摊、异常、年度账、对账和审计入口的页面一致性。
6. 必要的查询 DTO、详情安全投影和中央账本直接记录编辑契约。

不在范围内：重新设计财务实体、复制工资流水、改变工程量应收的自动生成规则、合并内外账权限、改变财务年度与员工年度的关系。

## 2. 已确认的交互决策

- 不使用浏览器可视化伴侣，以现有员工管理和工资台账代码为唯一视觉参照。
- 外部账本和内部账本保持两个独立入口。
- 业务分类使用真正的横向标签页，每次只显示一个业务区。
- 页面使用固定左右工作台：左侧汇总/快捷分类，右侧标签、筛选、表格和操作。
- 新增/编辑使用统一大弹窗外壳，顶部使用记录类型标签，切换后只显示当前类型字段。
- 查看详情使用大尺寸分区弹窗，不跳独立详情页。
- 资金、发票允许先登记为待分摊，支持部分分摊和后续完成。
- 直接创建且未分摊的记录可编辑；来源、已分摊、已对账、已关账记录锁定核心字段。
- 删除必须在独立确认弹窗中填写原因，并继续保留删除日志和审计快照。

## 3. 页面信息架构

### 3.1 外部账本

页面标题区只保留标题、说明、财务年度设置和“新增财务记录”。主体为两列：左列约 220px，右列占剩余宽度。

左列固定显示 6 个可点击核心卡片：应收未收、应付未付、本年收款、本年付款、待分摊、异常。卡片带上边框语义色；金额卡片使用表格同一套颜色，不使用仅靠红/绿的状态表达。

右列按标签切换：

- 总览：完整指标卡片、最近异常和结算主表。
- 应收/应付：结算主表，方向预设并保留其他筛选。
- 收款/付款：资金记录表，显示收付款账户、金额、已分摊、待分摊、来源和操作。
- 销项发票/进项发票：发票表，显示发票号、日期、含税金额、税额、已分摊、待分摊、来源和操作。
- 扣款：扣款表，显示关联结算、扣款金额、是否减少应开票、原因、来源和操作。
- 待分摊：同时显示待分摊资金和待分摊发票两个纵向卡片区，提供分摊入口。
- 异常：只显示超结算收付、超额开票、超前发票收付及分摊不一致的记录。
- 工资付款：沿用只读工资批次列表，操作跳转工资台账详情。
- 年度账/对账/修改记录：在同一工作台中显示说明卡、当前范围摘要和进入对应页面的操作；不在中央账本复制年度/对账实体。

### 3.2 内部账本

结构完全相同，但左列指标换成内部应收未收、内部应付未付、本年转入、本年转出、待分摊、异常。右列标签为总览、内部应收、内部应付、内部转账、内部发票、待分摊、年度账、对账、修改记录。表格永远显示本方自有公司和对方自有公司，不显示外部合作单位字段。

## 4. 数据契约与流转

### 4.1 查询 DTO

保留 `CentralLedgerOverviewPageDto.Rows` 作为结算主表，扩展可选集合：`Invoices`、`CashEntries`、`Deductions`、`UnallocatedInvoices`、`AuditEntries`。每个列表只返回当前用户可见账本范围的安全投影，不序列化 EF 导航对象。

新列表 DTO 至少包含：记录 ID、范围、方向、日期、公司/往来方显示名、项目、金额、已分摊、待分摊、来源类型、来源 ID、状态、并发版本和备注摘要。前端根据 `FinanceRecordType` 选择详情 URL，不把实体 JSON 直接放入 HTML。

### 4.2 详情

外部/内部页面提供 `OnGetDetailsAsync(type, id)` GET handler。handler 通过 `ICentralLedgerQueryService.GetAsync` 读取记录，服务层返回安全的 header JSON（只包含展示字段）和分摊集合。前端使用 `fetch` 加载，渲染分区弹窗：

1. 基本信息：编号、日期、方向、公司、往来单位/对方公司、项目、合同、来源。
2. 金额汇总：原始金额、扣款、实际金额、应开票、已开票、已收/已付、未收/未付、异常。
3. 分摊明细：每个目标结算、项目、合同和金额。
4. 关联记录：来源页、工资批次、项目、合作商、账户等可跳转链接。
5. 修改记录：审计动作、操作人、时间、原因；删除记录显示删除快照标识。

### 4.3 录入与编辑

`Entries/Edit` 保留 Razor Page 作为可链接入口，但页面内容改为自动打开的 `dialog` 工作区。类型标签为结算、扣款、发票、资金；`ledger-entry.js` 控制字段显隐、外部/内部字段、方向标签、金额预览和分摊预览。

服务层增加直接中央账本记录的更新契约。更新前必须携带并发版本并检查来源为 `CentralLedger` 且核心记录未发生分摊；已分摊记录只允许走分摊调整/调整记录。项目应收和工资付款继续禁止中央账本重复创建。

### 4.4 权限与安全

- 页面授权继续沿用现有角色；外部和内部 `CanManage` 不合并。
- 服务层继续校验自有公司、项目、内部对方公司、外部往来单位和方向。
- 分摊继续调用现有 `ValidateAllocationsAsync`，禁止跨范围、方向、公司或往来单位。
- 来源记录的中央账本操作列只显示查看、查看来源；不显示错误的编辑/删除按钮。
- 删除仍物理移除单头并留下 `FinanceDeletionLog`，但只能从二次确认弹窗触发，并要求原因；页面不再显示裸删除表单。
- 并发异常返回“已被其他用户修改，请刷新后重试”，详情弹窗关闭后保留当前筛选上下文。

## 5. 视觉与响应式规则

- 复用 `employee-workspace-layout`、`payroll-workspace-layout`、`data-workbench`、`workbench-dialog` 和 `entity-detail-*` 设计语言。
- 左列 `position: sticky`，顶部与页面内容对齐；桌面端两列底部对齐，右侧长列表在工作区内部滚动。
- 金额类使用 `ledger-amount--*` 语义类：收款/已收绿色，应收蓝色，应付紫色，待分摊琥珀色，异常红色，内部转账青色。
- 表格操作列统一使用 `action-button` 小按钮，至少包含查看；可编辑记录显示编辑；可分摊记录显示分摊；有来源记录显示来源。
- 表格使用固定列宽和 `overflow-wrap`，桌面首屏显示日期、方向、主体、金额、状态、操作；复杂说明使用两行截断并可在详情查看。
- 弹窗主体 `overflow-y: auto`，标题和底部操作固定；移动端左右工作台堆叠，表格只在局部滚动。

## 6. 错误处理与空状态

- 每个标签都有独立空状态，说明当前筛选范围和下一步可操作入口。
- 分摊金额超限、主体不匹配、内部公司相同、项目应收重复创建等服务异常显示在弹窗验证区。
- GET 详情失败显示可重试提示，不破坏当前页面筛选。
- 任何保存成功后返回原账本页面，并保留 `view`、年度、日期、公司、关键词和分页参数。

## 7. 测试策略

- 保留现有中央账本领域、应用服务、授权和集成测试。
- 增加页面源码测试：真实标签、左右工作台、详情 handler、统一弹窗、来源只读和删除确认。
- 增加查询服务测试：外部/内部列表投影、待分摊发票/资金、来源字段和审计列表的范围过滤。
- 增加命令服务测试：直接记录更新的并发校验、已分摊核心字段拒绝、来源记录不可从中央入口删除（若入口标识为 CentralLedger）。
- 运行 `dotnet test EngineeringManager/tests/EngineeringManager.Tests/EngineeringManager.Tests.csproj` 和 `dotnet build EngineeringManager/EngineeringManager.sln`。
