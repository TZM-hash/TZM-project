# 修复所有项目总览与自动编号异常

## Goal

让所有项目的经营总览以真实工程量、收款和发票数据为准显示完整金额与比例，并将历史导入产生的超长自动编号和自动占位名称安全、统一地缩短。

## Requirements

- 项目存在有效工程量明细时，即使对应的中央账本工程量应收尚未生成，项目总览仍必须显示应收、未收、应开票和未开票数据。
- 已存在有效工程量应收的明细不得重复计算；已作废的应收不阻止工程量兜底。
- 正负工程量必须先按当前筛选范围合并净额，再计算应收和应开，负数扣减行不得被逐行按零忽略。
- 项目直接关联但未分摊到应收的收款和销项发票仍应计入已收、已开，并正确冲减未收、未开。
- 项目详情总览显示应收、已收、未收、应开、已开、未开、应付、已付、未付及对应比例。
- 历史未知日期不得显示为 `0001/1/1`，统一显示“日期待确认”；`BankTransfer` 等支付方式统一显示中文。
- 项目明细表中的长编号、单位名称和备注不得越过单元格覆盖相邻内容。
- 当前数据库中由旧资料导入自动生成的项目、合同、工程量、员工、合作单位、发票及 9 个签约公司编码全部缩短。
- 旧资料自动生成的合同、工程量、合作单位、签约公司和财务账户占位名称必须改为简短中文描述，不再拼接项目名、旧编号或“旧资料补导”等技术说明。
- 旧资料按付款原文自动补建的合作单位，无论原名称长短，都必须改为带短序号的“待确认单位0001”格式；原始名称只保留在修复映射和审计记录中。
- 新建项目自动创建的合同名称固定为简短的“主合同”，不得复制完整项目名称。
- 项目动态中的导入、创建和历史修复动作必须显示中文，不得直接显示 `Create`、`DataImport` 等内部动作键。
- 员工完整工作簿中的“应付款 / 已付款”等分区标题和零金额空白模板行不得被识别为员工或业务明细。
- 编号修复必须保持实体 ID 和外键关系不变、避免唯一键碰撞、支持重复执行，并生成旧编号到新编号的映射报告。
- 旧资料转换脚本后续生成短项目编号，员工工作簿自动补号也使用统一的短格式。
- 项目、员工、合作单位和施工班组的新建/复制入口必须建议下一个标准短编号，不再拼接 `-COPY`；公司和设备复制名称统一使用紧凑中文“（副本）”。
- 历史发票类型字段中的 `Output` / `Input` 等方向值必须在页面上显示为“销项发票”/“进项发票”。
- 修改测试数据库前必须生成 SQL Server 完整备份；修复失败时不得留下半完成编号。

## Constraints

- 不为缺少合同客户的项目虚构合作单位，也不为未知日期伪造业务日期。
- 不修改用户手工维护且不符合旧资料自动编号前缀的编号。
- 当前工程量没有历史生效日期，因此带截止日期的历史财务查询不使用工程量兜底，避免把当前工程量倒灌到过去时点。
- 不提交现有 `.artifacts/`、`.tmp-*`、`outputs/`、`build_data_cleanup.mjs` 等一次性产物。

## Acceptance Criteria

- [ ] 截图项目 `XM0007` 显示工程量应收 `1,211,576.00`、已收 `1,105,550.00`、未收 `106,026.00`，收款率 `91%`、开票率 `81%`。
- [ ] 任一活动项目的当前汇总满足：应收包含所有未生成有效工程量应收的有效清单金额，且同一清单不重复计算。
- [ ] 直接项目收款和销项发票分别计入已收和已开，并正确冲减未收和未开。
- [ ] 项目详情顶部与“金额进度”区域能看到应收/已收/未收、应开/已开/未开、应付/已付/未付及比例。
- [ ] 项目明细不再显示 `0001/1/1`、`BankTransfer`，长内容不再覆盖相邻列。
- [ ] 全库 227 个项目、227 个合同、737 条工程量、96 个旧员工、462 个合作单位、482 张发票及 9 个签约公司不再使用 `OLD-*` 或 `OFFICIAL-*` 自动编号。
- [ ] 项目 `XM0007` 的自动合同名显示“主合同（待确认）”，空名称工程量按合同显示“待确认工程量1/2/3”，不再显示旧长编号。
- [ ] 全库自动占位名称不再包含“原始主合同（待确认）”“待补工程量-”“（旧资料补导）”；合作单位、签约公司和财务账户分别显示简短名称“待确认合作单位”“待确认签约公司”“待确认账户”。
- [ ] 旧资料自动补建的 183 个合作单位全部显示为“待确认单位+短序号”，名称和简称均不再包含身份证号、银行卡号或整段付款原文。
- [ ] 含负数扣减工程量的项目，应收和应开与工程量净额一致；`XM0007` 的应收净额为 `1,211,576.00`。
- [ ] 新建项目自动生成的主合同名称为“主合同”。
- [ ] 新编号格式为项目 `XM0001`、合同 `XM0001-C01`、工程量 `QD001`、员工 `YG0001`、合作单位 `HZ0001`、发票 `FP000001`、签约公司 `GS0001`，遇到已有编号时自动顺延。
- [ ] 新建和复制项目、员工、合作单位或施工班组时，页面建议值仍分别符合 `XMdddd`、`YGdddd`、`HZdddd`，且计算项目编号时包含停用项目，避免重复。
- [ ] 所有复制入口不再生成 `-COPY` 或“ - 副本”，复制名称仅增加紧凑中文“（副本）”。
- [ ] 编号修复命令第二次执行不再产生变更。
- [ ] 员工库不再存在名称为“已付款”等分区标签的伪员工，重新预览原始工作簿也不会生成此类员工。
- [ ] 项目动态中的系统动作均显示中文。
- [ ] 项目开票明细不再显示 `Output` / `Input`，统一显示中文发票方向。
- [ ] 修复前备份存在，修复后全库审计无重复编号、无丢失实体、无断开的项目财务关联。
- [ ] 定向测试、脚本测试、完整测试和 Release 构建通过，真实服务页面复核通过。
