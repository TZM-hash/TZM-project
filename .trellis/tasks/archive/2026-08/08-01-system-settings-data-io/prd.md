# 系统设置与数据导入导出完善

## Goal

在不破坏既有数据和未提交改动的前提下，补齐系统设置、页面切换性能、项目财务总览、员工 Excel 数据导入、中文化、编号和标准导入导出，使现有测试库中的业务数据可以完整展示、持续维护和交换。

## Requirements

1. 在系统设置增加全局字体大小，默认保持当前标准字号；提供小、标准、大、特大四档，持久化、缓存、审计、页面预览和全站生效。
2. 修复页面直接跳转切换卡顿：首屏不再等待非关键模块，导航即时反馈，重型图表/表格/离线能力延后初始化，并降低过强的页面进入动效。
3. 修复项目总览财务数据缺失：项目级收款、付款、发票即使没有结算分摊也要计入；总览显示金额及对应比率；批量项目汇总不能逐项目执行重型查询。
4. 根据 `old-data/员工相关信息2026年.xlsx` 的已计算公式和表间关系导入员工工资、已发、未发、调整、收款/往来等明细；建立或复用 2026 业务年度；重复执行必须幂等并保留可追溯来源。
5. 面向用户的显示字符串、枚举标签、导入导出标题和错误信息统一为中文；内部代码标识、数据库字段和兼容导入别名不强制改名。
6. 缩短自动生成的业务编号，在不改变唯一性和现有编号可查询性的前提下使用短前缀+日期/序号；不回写破坏既有历史编号。
7. 完善与现有系统模型一致的导入导出格式：模板列名、必填列、枚举中文值、金额/日期格式、关联字段、错误报告和导出回读一致；财务中央账本、工资批次及员工往来均可导出，发票不再只读空旧表。

## Constraints

- 只修改当前任务相关的业务代码、测试、模板和补导脚本；保留已有未提交文件。
- 使用测试库 `EngineeringManager_Test` 验证导入；不操作生产库、不执行远程 Git、不删除用户文件。
- Excel 公式结果以工作簿缓存值和可复算规则为准；金额使用 decimal，未付金额按应付减已付并按表内调整项校正。
- 旧导入格式和已有历史编号继续兼容；新模板提供中文列名，同时允许稳定的内部键作为关联列。

## Acceptance Criteria

- [ ] 新用户默认字号为标准档，保存后刷新/重新进入页面仍生效，四档字号在主要布局和表格中可见。
- [ ] 导航点击不等待所有动态模块，关键内容先展示；页面切换相关测试和性能基准不回退。
- [ ] 至少一个仅有项目级现金/发票、没有结算分摊的项目在总览中正确显示收款、付款、发票金额和比率；批量查询只执行有限的聚合查询。
- [ ] 员工 Excel 中的员工工资应发、已发、未发和可用往来明细导入后与公式结果核对，重复运行不产生重复业务记录。
- [ ] 用户可见英文枚举/状态/模板标题替换为中文，关键页面无英文占位标签或 `ToString()` 直出。
- [ ] 新生成编号长度明显缩短且同一业务范围内唯一；历史编号仍可查询。
- [ ] 导出模板可下载、导出数据可重新导入；中央账本收款、付款、发票、员工工资/往来均有中文模板和错误报告。
- [ ] 相关单元/应用/Web 测试通过，解决方案构建通过，测试库数据校验报告生成。
