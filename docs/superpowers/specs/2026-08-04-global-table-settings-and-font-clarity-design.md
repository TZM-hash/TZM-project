# 全站列管理保存与字体清晰度优化设计

## 背景与根因

共享数据工作台已经把列显隐、列顺序、行距和分页大小写入浏览器 `localStorage`，键名为 `engineering-manager-workbench:<pageKey>:<tableId>`。但 `data-table.js` 的初始化顺序先使用服务器保存视图的列配置，再读取本地配置，因此服务器视图可能覆盖用户最近一次列管理设置。

字体模糊问题可以由用户反馈“鼠标移动到页面时出现”稳定定位到悬停动画。`themes.css` 在 Technology 和 Apple 动效下会对 `.panel:hover` 做位移或缩放，而 `.panel` 可能承载整张表格和大量正文。浏览器对被 `transform` 的整块内容进行合成层栅格化时，文字会在悬停期间发虚，尤其是带缩放的 Apple 动效。

## 设计方案

### 1. 列管理本地持久化

- 保留现有 `localStorage` 键名和状态结构，不增加数据库表或服务器接口。
- `_DataWorkbench.cshtml` 暴露当前是否明确选择了服务器保存视图的标记。
- 普通页面进入时，初始化优先级为：
  1. 当前浏览器中已有的本地列状态；
  2. 页面传入的服务器保存视图列状态；
  3. 页面默认列状态。
- 用户明确选择服务器保存视图时，该视图作为本次显式操作的优先来源；初始化后立即写入本地状态，使其成为之后普通重新打开页面时的“最后一次设置”。
- `normalizeColumns` 继续负责兼容列变化：固定列始终可见，未知列忽略，新列按默认顺序补齐。
- 本地存储不可用或 JSON 损坏时静默回退到服务器视图或页面默认值，不阻止列表使用。
- “恢复默认”只修改当前列管理草稿，仍由“确认”触发 `persist`；取消、Escape 和点击菜单外部不会覆盖已有本地状态。

### 2. 悬停时保持文字清晰

- 删除两种动效模式中针对 `.panel:hover` 的 `transform` 位移/缩放规则。
- 保留 `.metric-card:hover` 的轻微动效，因为指标卡不承载长表格正文；面板仍可通过阴影、边框或背景色表达悬停状态。
- 不修改字号、页面网格、表格宽度、主题颜色或响应式断点，也不改变背景装饰和对话框的独立动效。

## 数据流与兼容性

列状态仍只在当前浏览器/当前电脑生效，不跨设备同步。服务器保存视图功能保持可用；显式选择保存视图时仍可应用其筛选、排序、行距和列配置，之后本地列设置会记录这次选择。

## 错误处理

- 所有 `localStorage` 读取和写入继续使用 `try/catch`。
- 本地状态必须经过现有列规范化逻辑后才能应用，避免旧版本列键、固定列或新增列造成异常。
- 如果用户尝试隐藏全部非固定列，保留当前至少一列可见的保护逻辑。
