# 合作单位统一分类与项目名称同步设计

**日期：** 2026-08-06
**状态：** 已按用户自动授权确认，待实施
**参考：** 现有合作单位、甲方/总包、施工班组工作台及项目工作簿导入

## 1. 目标

将左侧独立的“甲方/总包”“施工班组”“合作单位”入口合并为一个“合作单位”工作台，并解决当前列表在中等宽度下名称、角色、金额和操作区相互挤压的问题。

统一工作台提供四个分类视图：

1. 全部。
2. 施工班组。
3. 甲方/总包。
4. 其他合作单位。

分类不新增独立数据库字段，直接由合作单位业务角色派生，避免“单位类型”和“业务角色”形成两套不一致数据。

## 2. 分类规则

- 含 `ConstructionCrew` 角色的单位进入“施工班组”。
- 含 `CustomerOrGeneralContractor` 角色的单位进入“甲方/总包”。
- 不含以上两种角色的单位进入“其他合作单位”，包括材料供应商、零星供应商和历史未分类单位。
- “全部”对每个单位只显示一次。
- 多角色单位可同时出现在多个对应分类中，这是业务角色的真实反映，不复制单位主档。

编辑单位时，页面同时提交本次编辑前的角色。若角色发生变化，只替换旧角色为新角色，保留该单位其他并行业务角色。这样单角色单位会立即移动到新分类，多角色单位也不会丢失无关角色。

## 3. 页面与路由

`/Partners` 作为唯一顶级合作单位工作台：

- 页面顶部显示“全部 / 施工班组 / 甲方·总包 / 其他合作单位”分类标签和数量。
- 原有搜索、角色、状态筛选继续保留，并与分类共同生效。
- 施工班组行提供进入班组专属档案的入口，以保留人员名册、工资记录和部门维护能力。
- 通用详情、财务、组织统计和编辑继续复用合作单位现有能力。

兼容策略：

- `/Crews` 列表路由重定向至合作单位的施工班组分类。
- `/Partners/customers` 重定向至合作单位的甲方/总包分类。
- `/Crews/Details` 等现有深链接继续可用，避免历史收藏、项目跳转和测试失效。
- 左侧导航只保留一个“合作单位”顶级入口。

## 4. 项目数据自动补齐

新增幂等的项目合作单位目录同步逻辑，数据来源包括：

1. 项目的总包名称字段。
2. 项目合作单位关联及其角色。
3. 项目施工记录中的班组单位。

同步行为：

- 先按单位全称或简称进行忽略大小写的规范化匹配。
- 匹配到已有单位时，只补缺失角色和缺失项目关联，不覆盖编号、联系人、信用代码、备注或启停状态。
- 未匹配到单位时创建启用主档，自动生成不冲突的 `HZ` 编号，简称取规范化短名称。
- 总包名称会补 `CustomerOrGeneralContractor` 角色及对应项目关联。
- 项目合作单位关联会把关联角色补到单位主档。
- 施工记录会确保对应单位拥有 `ConstructionCrew` 角色。
- 重复执行不会创建重复单位、角色或项目关联。

同步在以下入口执行：

- 打开合作单位工作台时，用于补齐已经导入的历史项目数据。
- 项目新增、项目概览修改和项目工作簿确认导入后，用于保证后续数据即时一致。
- 通用合作单位导入支持可选“业务角色”列，新增或更新时同步角色。

同步不删除用户数据；开发验证仅使用测试数据库，不连接或修改生产数据库。

## 5. 排版修复

合作单位和施工班组使用同一套可读性规则：

- 中等宽度下提前把左侧概览移到列表上方，为主表释放横向空间。
- 表格保持在自身容器中滚动，不产生页面级横向溢出。
- 单位名称最多显示两行并提供完整标题提示。
- 角色、专业、联系人和次要信息使用单行省略，避免一行被撑成多层文本块。
- 金额标签与数字保持同组对齐，操作按钮不折行。
- 小屏继续使用内部横向滚动，弹窗表单改为单列。

检查同类工作台页面；只对复现相同结构问题的页面应用共享规则，不做无关视觉重构。

## 6. 错误处理与审计

- 角色替换继续使用并发标记和修改原因，并记录修改前后角色。
- 自动同步若发现同名对应多个单位，不猜测合并，跳过该名称并保留现有数据。
- 自动编号在当前单位编号集合中寻找下一个可用值，避免唯一索引冲突。
- 同步、项目保存和导入确认位于各自事务边界内，失败时整体回滚。
- 旧的无角色单位继续显示在“其他合作单位”，不会从页面消失。

## 7. 测试与验收

自动化测试至少覆盖：

- 四个分类的派生、数量和组合筛选。
- 角色修改后分类自动变化，同时保留无关的其他角色。
- 历史项目总包名称自动创建或匹配单位，并建立项目关联。
- 项目合作单位和施工记录补齐缺失角色。
- 同步重复执行不产生重复单位、角色或项目关联。
- 通用合作单位导入可写入并更新业务角色。
- 旧 `/Crews` 和 `/Partners/customers` 列表地址正确兼容跳转。
- 左侧导航只显示一个合作单位入口。
- 合作单位与施工班组列表在 1440、1366 和 390 像素视口下无页面级横向溢出，表格仅在内部滚动，文字和操作区不重叠。

完成标准：项目中已有的总包和班组数据能在正确分类中看到；修改单位角色后分类即时改变；既有班组深层功能和历史链接继续可用；相关列表排版清晰稳定。
