# 员工管理与合作商管理体验对齐设计

## 目标

以现有合作商管理工作台为唯一视觉与交互参考，统一员工管理大类的显示风格、操作逻辑、排版和弹窗，使用户在两个主档模块之间切换时获得一致的操作体验，同时保留员工独有的业务数据与权限规则。

## 范围

- 员工列表、员工新增与编辑、员工详情、员工证书、员工年度账及员工子导航页面。
- 独立的工资管理和中央账本不改版，仅保持现有来源跳转与数据联动。
- 不修改数据库结构、财务计算口径、员工领域模型、共享契约或权限边界。

## 总体方案

采用“合作商工作台结构复刻、员工业务内容适配”的方式：员工页面复用合作商管理已验证的双栏布局、工具栏、表格密度、操作按钮、窗口弹窗和响应式规则，但不强行抽取新的跨模块共享组件，避免扩大回归范围。

## 员工列表工作台

- 页面顶部使用合作商管理同款紧凑标题区和主操作按钮。
- 主体使用左侧概览、右侧主档表格的双栏结构；窄屏下改为上下排列。
- 左侧显示员工总数、在职/停用数量、员工类型分布，并支持按类型快速筛选。
- 右侧将筛选、列管理和保存视图工具栏集成到列表标题区。
- 表格沿用员工现有字段、脱敏结果和权限可见性，但统一合作商表格的字号、间距、状态标签、空状态及操作列布局。

## 弹窗与操作逻辑

- 新增、查看、编辑和复制统一从员工列表以合作商同款窗口弹窗打开。
- 查看态只读；编辑态回填现有员工数据；复制态复制可复用资料并清空员工编号等唯一字段；新增态使用空表单。
- 弹窗统一标题栏、关闭按钮、底部操作区、取消行为、Esc/遮罩关闭规则和保存中状态。
- 保存失败时保留已输入内容并在弹窗内显示验证信息；并发冲突沿用现有并发标记和错误反馈。
- 成功保存后仍由服务端重定向回当前筛选视图，避免破坏既有授权与校验流程。

## 详情及子页面

- 员工详情保留工资、报销、借支、付款记录、证书及年度数据等员工专属内容。
- 标题区、子导航、卡片边界、信息密度、按钮层级、状态反馈和辅助文字统一合作商管理的视觉语言。
- 员工证书和年度账页面统一工作台工具栏、表格、空状态、操作按钮及响应式排版。
- 详情页到工资管理和中央账本的现有来源链接保持不变。

## 权限与敏感信息

- 新增、编辑、复制继续受现有员工管理权限控制。
- 身份证、银行卡等敏感字段继续由服务端按当前权限脱敏，不在浏览器端保留未授权原值。
- 只读用户只显示查看操作，不渲染可写表单或可写入口。

## 错误处理与兼容

- 保留现有服务端 ModelState 校验、业务错误、并发冲突和权限拒绝语义。
- 旧员工详情、编辑及业务年度链接继续可访问；列表操作切换为弹窗不删除兼容入口。
- JavaScript 不可用时，关键查看和编辑入口应继续具备可访问的页面回退路径。

## 验证

- 页面模型测试：员工筛选、权限、脱敏、编辑回填、复制初始化和重定向参数。
- 页面契约测试：双栏工作台、概览指标、集成工具栏、统一操作按钮和弹窗结构。
- JavaScript 定向测试：弹窗打开/关闭、模式切换、数据回填、复制清理和错误态保持。
- 回归测试：员工列表、员工详情、员工证书、员工年度账及响应式资源测试。
- 构建验证：相关测试通过后执行项目 Release 构建。

## 验收标准

1. 员工管理大类在布局、信息密度、按钮、状态、弹窗及响应式行为上与合作商管理保持一致。
2. 新增、查看、编辑和复制均可在员工列表工作台完成，权限和服务端校验不退化。
3. 员工详情及子页面保留全部员工专属业务能力，并使用统一视觉语言。
4. 工资管理、中央账本、财务计算、数据库结构和既有深链接不受影响。
