# 项目管理页格式导出设计

## 目标

项目管理页的“导出项目清单”必须导出当前页面实际展示的数据语义：使用同一组筛选条件、同一排序方向、同一项目选择范围，并让列管理中的可见性和顺序同步到 Excel。默认导出为单个“项目清单”工作表；勾选附件文件时，工作簿仍放入 ZIP 并附带附件清单和文件。

## 范围与兼容性

- 项目管理页的导出入口使用页面格式导出路径。
- 项目详情页、数据交换页继续使用现有多工作表导入/导出协议，避免改变已有导入模板和权限边界。
- 页面导出的“当前筛选全部项目”不受当前分页限制；手动勾选只导出勾选项目。
- 页面格式导出不包含选择框和操作列；固定序号列以及页面数据列可按列管理结果导出。
- 附件 ZIP 仍遵守现有授权、文件存储、manifest 和校验和规则；不勾选附件时只返回 `.xlsx`。

## 架构

在 `ProjectWorkbookExportRequest` 增加可选的页面清单配置。`ProjectWorkbookService` 继续负责授权和导出任务记录；`ProjectWorkbookExporter` 根据配置选择现有工作簿路径或新的页面清单路径。页面清单路径调用项目查询服务获取完整匹配 ID 顺序，再按该顺序加载所有匹配项目和财务摘要，避免重新按项目编号排序或受到 20/50/100 分页限制。

页面列由稳定的列键白名单定义，服务端过滤未知、重复和操作列键；未提供或全部无效时使用页面默认列。Excel 表头、文本占位符、日期、金额、中文状态和收款/付款/开票进度字符串由同一个页面导出映射集中生成。进度列保持页面的“百分比 + 应/已/未金额”信息，Excel 不模拟 CSS 进度条。

前端在项目导出表单中输出每个页面列的隐藏 `ExportColumns` 输入。`data-table.js` 在列管理应用时同时禁用隐藏列并按当前列顺序重排这些输入；浏览器未启用脚本时服务端仍使用默认列。项目查询参数继续由现有隐藏字段提交，因此筛选和排序由服务端重新计算，不能被客户端篡改。

## 数据流

1. 用户在项目管理页设置筛选、排序、分页、勾选和列管理。
2. 导出表单提交查询参数、`SelectAllMatching`、`SelectedProjectIds`、`IncludeWorkbookAttachments` 和 `ExportColumns`。
3. 页面模型构造页面格式导出请求；服务端根据当前用户重新解析授权范围和筛选结果。
4. 导出器保留查询服务返回的匹配顺序，选择全部匹配或按该顺序过滤手动选择。
5. 导出器生成“项目清单”工作表；附件模式追加“附件清单”并创建现有 ZIP 包。
6. 服务记录实际文件格式、行数、筛选条件和导出数据集。

## 错误处理与安全

- 当前用户、项目范围、工作表/附件权限仍由 `ProjectWorkbookService` 统一校验。
- 空选择继续返回“请至少勾选一个项目，或选择导出当前筛选命中的全部项目”。
- 查询后没有授权匹配项目时继续抛出“没有可导出的项目”。
- 页面列键只接受白名单值，不能通过表单注入任意数据库字段或 HTML。
- 附件哈希、文件存储缺失和 ZIP manifest 行为保持现有实现。

## 验收标准

- 同一筛选和排序下，Excel 项目顺序与页面完整匹配顺序一致。
- 当前筛选全部项目导出数量不受当前页面大小影响；手动选择只包含勾选项目。
- Excel 表头顺序与页面列管理顺序一致，隐藏列不导出，操作列不导出。
- 项目编号、名称、阶段、中文状态、金额、日期和三类进度的显示文本与页面一致。
- 不勾选附件返回单个 Excel；勾选附件返回 ZIP，包含项目清单、附件清单、manifest、校验和及授权项目附件。
- 现有项目工作簿导入/导出和附件 ZIP 回归测试保持通过。
