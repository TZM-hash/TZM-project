# 项目金额与清单项数量清理设计

## 现状与结论

项目工程量明细实际持久化 `Quantity` 与 `UnitPrice`。`EstimatedQuantity`、`EstimatedUnitPrice`、`SettledQuantity`、`SettledUnitPrice` 是 `ContractLineItem` 上的非持久化兼容属性；新增和编辑时根据暂估/结算口径选择值，最终写回统一字段。`ProjectSummaryService` 使用统一字段计算 `CurrentAmount`。

`ProjectAmountCalculator` 当前额外返回 `EstimatedAmount` 和 `SettledAmount`，但二者只是根据项目阶段将同一 `CurrentAmount` 放入不同桶中：未结算阶段为预计金额，部分/已结算阶段为已结算金额。项目列表、项目导出和项目经营汇总因此重复展示同一金额。`LineItemCount` 只用于项目列表/导出，以及项目详情标签上的数量徽标，不参与业务计算。

## 方案

采用项目汇总契约收敛方案：

1. 将 `ProjectAmountSummary` 与 `ProjectSummaryDto` 收敛为合同金额、当前工程金额、结算状态、合同数量和应开票工程金额；删除项目汇总层的预计金额、已结算金额和清单项数量。
2. 保持当前工程金额的计算实现不变，只删除不再需要的分桶结果及其测试断言。
3. 同步删除项目管理 Razor 列表、列管理/导出列定义、传统项目清单导出、项目经营汇总工作簿目录与行映射中的三个字段。
4. 删除项目详情“工程量明细”标签的数量徽标，但保留明细表、暂估/结算口径选择、工程量编辑和小计预览。
5. 更新领域、应用、Web 和数据交换测试，增加字段不存在/旧列配置被过滤的回归覆盖；不修改数据库 schema 或数据迁移。

## 边界

- 保留 `ContractLineItemDto` 的暂估/结算字段和 `ContractLineItem` 的兼容属性，因为它们服务于工程量录入时的口径选择与财务过渡逻辑。
- 保留项目 `SettlementStatus`，它仍用于阶段状态展示和排序。
- 保留合同金额、当前工程金额、收付款、开票、结算状态及工程量明细导入导出。
- 不删除设备模块的累计结算金额、财务模块的已收/已付金额或其他与项目汇总无关的同名字段。

## 数据流与错误处理

工程量明细 `Quantity/UnitPrice` -> `ProjectAmountCalculator.CurrentAmount` -> 项目汇总 DTO -> 项目列表、详情和导出。此次只删去 DTO 之外的冗余投影，不改变输入校验、空值按零计算、发票口径或授权过滤。旧的保存列配置通过现有列定义归一化，仅匹配当前有效列，因此删除字段后不会恢复显示。

## 验证策略

- 运行领域金额计算、项目服务、项目工作台和数据交换相关测试。
- 运行 Web 页面字符串/列布局测试，确认三个字段不再注册或渲染，工程量明细标签仍存在但无数量徽标。
- 运行完整解决方案测试、构建和项目质量门禁；最后全文检索项目层冗余字段引用。
