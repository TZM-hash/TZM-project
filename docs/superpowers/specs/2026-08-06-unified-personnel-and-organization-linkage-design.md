# 统一人员管理与组织联动设计

**日期：** 2026-08-06
**状态：** 用户已确认总体方案，待书面规格复核
**适用模块：** 人员管理、自有公司、施工班组、合作单位、项目管理

## 1. 目标

本轮把现有“员工管理”升级为“人员管理”，解决人员档案分散、内部与外部身份无法连续转换、当前归属只读，以及公司、班组、合作单位缺少部门和可下钻统计的问题。

完成后应满足：

1. 同一个自然人只有一个统一人员主档。
2. 内部人员、外部人员是可带生效日期切换的身份，不通过复制档案实现转换。
3. 当前公司、当前部门、当前项目、当前班组可编辑，并由同一份时效归属历史联动计算。
4. 当前项目读取最新生效的人员项目归属；新建或调整更晚生效的项目归属后自动更新，不按全系统项目创建时间猜测。
5. 自有公司、施工班组和合作单位均可维护自己的部门，并可将人员归属到具体部门。
6. 三类组织页面均显示项目状态和人员状态统计；点击统计项可跳转到已带筛选条件的项目页或人员页。
7. 工资、证件、付款、项目、班组和审计历史始终关联同一个人，身份切换不切断历史。

## 2. 已确认的方案选择

### 2.1 采用方案：统一人员主档 + 业务档案桥接

新增统一 `Person` 主档保存自然人的公共身份信息。现有 `Employee` 与 `ConstructionWorker` 暂时保留，作为内部员工和施工班组人员的业务档案，并分别以唯一外键关联 `Person`。

这样可以在不一次性重写工资、证书、班组名册和历史付款外键的前提下，实现统一人员列表、身份切换和连续历史。公共资料只允许从统一人员服务维护，兼容字段由服务在同一事务内同步。

### 2.2 未采用的方案

1. **内部、外部各建一份档案：** 实现最快，但会造成身份证、银行卡、工资、证书和项目历史重复，无法可靠判断是否为同一个人，因此不采用。
2. **一次性把 `Employee`、`ConstructionWorker` 全部合并为单表：** 最终模型最简洁，但会同时影响工资、班组名册、付款、导入导出和大量历史外键，迁移风险过高，因此本轮不做大爆炸式重构。

## 3. 范围与非目标

### 3.1 本轮范围

- 统一人员主档、身份历史和当前归属历史。
- 内部人员与外部人员两类工作台。
- 内部/外部身份转换。
- 黄色框四项归属的联动编辑。
- 公司、班组、合作单位的部门维护。
- 公司、班组、合作单位的项目和人员统计及筛选下钻。
- 现有员工、班组人员和归属历史的安全回填。
- 旧员工及班组人员路由兼容。

### 3.2 非目标

- 不删除现有工资、员工、班组人员或付款业务表。
- 不根据姓名、手机号等弱特征自动合并历史人员。
- 不改变中央账本、工资金额和结算金额的唯一数据源。
- 不在组织统计页复制项目或人员业务数据。
- 不建设审批流、考勤系统或人力资源招聘流程。
- 不物理删除已被人员引用的部门或身份历史。

## 4. 核心数据模型

### 4.1 统一人员主档 `Person`

公共字段包括：

- `Id`
- 统一人员编号
- 姓名
- 身份证号
- 手机号
- 银行卡号
- 开户行
- 备注
- 启用状态
- 创建时间、更新时间、并发标记

身份证号非空时使用标准化值建立唯一约束。敏感资料继续由服务端依据现有敏感人员权限脱敏。

### 4.2 业务档案桥接

- `Employee.PersonId`：唯一且必填；保留员工类型、默认工资单价、员工编号、负责人资格等内部业务字段。
- `ConstructionWorker.PersonId`：唯一且必填；保留施工工种、班组工资和班组名册所需业务关系。
- 普通合作单位的外部人员不强制创建 `ConstructionWorker`；只有进入施工班组名册时才创建或关联班组人员业务档案。

统一人员服务是姓名、身份证、电话、银行卡和启停状态的唯一编辑入口。兼容业务档案中的同名字段在同一事务内更新，旧服务不得形成可独立修改的第二份公共资料。

### 4.3 身份与归属历史 `PersonnelEngagementHistory`

每条记录包含：

- `PersonId`
- 人员范围：`Internal` / `External`
- 内部子类型：正式员工、劳务员工、特殊临时人员；仅内部身份使用
- 外部子类型：施工班组人员、合作单位人员、其他外部人员；仅外部身份使用
- 自有公司 `LegalEntityId`，可空
- 所属合作单位 `BusinessPartnerId`，可空
- 部门 `OrganizationUnitId`，可空
- 项目 `ProjectId`，可空
- 当前班组 `CrewBusinessPartnerId`，可空
- 岗位或工种
- 生效日期、结束日期
- 是否主要归属
- 备注、并发标记

同一个人在任意日期只能有一条主要身份归属。身份切换或归属调整时关闭旧记录，并新增一条记录；不覆盖旧记录。

### 4.4 部门归属

继续复用 `OrganizationUnit`，避免再造一套部门表，并扩展以下所有权信息：

- `LegalEntityId`：部门属于某家自有公司时填写。
- `BusinessPartnerId`：部门属于某个施工班组或合作单位时填写。
- `IsAuthorizationScope`：是否可作为系统用户的数据权限组织单元。

约束规则：

- 自有公司部门只能设置 `LegalEntityId`。
- 施工班组或合作单位部门只能设置 `BusinessPartnerId`。
- 同一部门不能同时属于自有公司和合作单位。
- 现有系统级部门或分支机构可以两者都为空，并继续用于权限范围。
- 外部组织部门默认 `IsAuthorizationScope = false`，不能误用于系统用户权限成员关系。
- 已被引用的部门只能停用，不能物理删除。

## 5. 人员分类与身份切换

### 5.1 页面分类

主导航“员工管理”改为“人员管理”，下设：

- 内部人员：现有正式员工、劳务员工、特殊临时人员。
- 外部人员：施工班组人员、合作单位人员和其他外部人员。

推荐路由：

- `/Personnel/Internal`
- `/Personnel/External`
- `/Personnel/Details/{personId}`

旧 `/Employees`、`/Employees/Details/{employeeId}` 和班组人员入口继续兼容，跳转到对应统一人员范围或详情，不让已有书签失效。

### 5.2 身份切换操作

人员详情提供：

- “转为外部人员”
- “转为内部人员”

切换弹窗必须填写：

- 生效日期
- 新身份子类型
- 所属公司或合作单位
- 部门
- 项目
- 班组
- 岗位或工种
- 修改原因

保存规则：

1. 旧主要身份的结束日期设为新身份生效日前一天。
2. 新增主要身份历史。
3. 转为内部人员时，若不存在 `Employee` 业务档案则创建；已有档案重新启用并保留全部旧历史。
4. 转为施工班组人员时，若不存在 `ConstructionWorker` 业务档案则创建，并写入对应班组成员关系。
5. 转为普通合作单位人员时不强制创建施工班组档案。
6. 所有步骤与审计记录在同一事务内完成；任一失败整体回滚。

同一人员可以多次在内部和外部之间切换，但不能存在重叠的主要身份区间。

## 6. 黄色框四项联动编辑

人员详情“当前归属”区域把以下四项从只读改为可编辑下拉框：

- 当前公司或所属单位
- 当前部门
- 当前项目
- 当前班组

### 6.1 联动规则

- 内部人员先选择自有公司；部门候选只显示该公司的启用部门。
- 外部人员先选择施工班组或合作单位；部门候选只显示该单位的启用部门。
- 项目候选只显示所选公司或合作单位已经关联的启用项目。
- 当前班组只显示具有施工班组角色且启用的合作单位。
- 外部身份所属单位本身就是施工班组时，当前班组自动选择该单位并保持一致。
- 改变上级选择后，已不再有效的部门、项目或班组值必须清空，不能提交隐藏的旧值。

### 6.2 当前项目计算

“当前项目”不是独立缓存字段，而是从主要归属历史读取：

1. 取当前日期有效的主要归属。
2. 若有多条历史候选，取生效日期最新的一条。
3. 新建更晚生效的项目归属后，页面自动读取新项目。
4. 项目停用或归档时保留历史显示；新编辑候选只列启用且符合组织关系的项目。

保存当前归属时不直接覆盖原记录，而是按照选定生效日期关闭旧记录并创建新记录。

## 7. 组织部门管理

自有公司、施工班组和合作单位页面均新增“部门设置”区域或标签，提供：

- 新增部门
- 编辑部门编码、名称、上级部门和排序
- 启用或停用部门
- 查看当前人员数
- 点击人员数进入人员管理筛选页

部门编码在同一组织内唯一，不要求跨所有组织全局唯一。上级部门必须属于同一组织，禁止跨公司或跨合作单位挂接。

自有公司的既有系统组织单元不自动猜测归属。迁移时只有能从现有人员主要归属中唯一确定公司的部门才自动建立公司归属；有歧义的部门继续作为系统级组织单元，并在管理页显示“待指定所属公司”。

## 8. 自有公司、施工班组和合作单位统计

### 8.1 项目状态统计

每个组织按去重后的关联项目显示：

- 项目总数
- 待进场/进行中：`AwaitingMobilization`、`UnderConstruction`
- 暂停：`Suspended`
- 完工未结算：`CompletedUnsettled`
- 部分结算：`PartiallySettled`
- 已结算归档：`SettledArchived`

自有公司通过项目签约公司或合同分配关系统计；合作单位通过项目参与关系统计；施工班组在合作单位参与关系之外，还纳入施工详情中的班组进退场记录，并按项目去重。

点击统计项跳转项目管理，并携带真实筛选参数：

- 自有公司：`LegalEntityId`
- 施工班组/合作单位：新增 `BusinessPartnerId`
- 状态卡：`Stages`

项目列表服务增加 `BusinessPartnerId` 过滤能力，不能用关键词搜索模拟精确筛选。

### 8.2 人员状态统计

自有公司显示：

- 当前人员总数
- 正式员工
- 劳务员工
- 特殊临时人员
- 当前外部协作人员

施工班组显示：

- 当前人员总数
- 当前在组人员
- 已离组人员
- 内部派驻人员
- 外部班组人员

合作单位显示：

- 当前人员总数
- 当前在岗人员
- 已离岗人员
- 内部派驻人员
- 外部合作单位人员

所有统计均基于当前有效主要身份或归属，历史记录不计入“当前人数”。点击数字进入 `/Personnel/Internal` 或 `/Personnel/External`，并携带公司、合作单位、部门、人员子类型和状态筛选。

## 9. 页面与服务边界

### 9.1 人员管理

新增统一人员查询与命令服务，职责包括：

- 汇总 `Person`、内部员工业务档案、班组人员业务档案和当前身份。
- 处理内部/外部列表筛选。
- 保存公共资料。
- 保存当前归属。
- 执行身份切换。
- 返回完整身份与归属历史。

工资、员工年度总账、证书和班组工资仍由现有专项服务维护，统一人员详情只通过 `PersonId` 找到对应业务档案并跳转或聚合展示。

### 9.2 组织统计

新增统一组织摘要查询组件，输入组织类型和组织 ID，输出项目分组、人员分组和部门分组。公司、班组和合作单位页面复用同一统计定义，避免三个页面分别计算出不同口径。

统计服务只读，不保存统计快照；源项目、人员或部门发生变化后，下次请求直接反映最新数据。

### 9.3 项目筛选

扩展现有项目列表查询合同，增加可空 `BusinessPartnerId`。筛选同时覆盖：

- `ProjectPartner` 参与关系。
- 施工班组的项目施工记录。

若同时提供公司、合作单位和阶段筛选，按交集查询。

## 10. 数据迁移与兼容

迁移采用加法方式，不在首轮删除旧字段或旧表：

1. 为每个现有 `Employee` 创建或关联一个 `Person`。
2. 为每个现有 `ConstructionWorker` 创建或关联一个 `Person`。
3. 身份证号标准化后完全一致、两侧各只有一条且无字段冲突时，可以自动关联为同一人。
4. 身份证重复、多条匹配或关键资料冲突时不得自动合并，分别建档并记录迁移冲突。
5. 不使用姓名、手机号或银行卡作为自动合并依据。
6. 现有员工主要归属迁移为内部身份历史。
7. 现有班组当前成员关系迁移为外部施工班组身份历史。
8. 旧员工与班组人员业务外键保持不变，通过 `PersonId` 汇总。

新版本投入使用后，所有新增人员必须先创建 `Person`。旧页面保存入口改为调用统一人员服务或兼容跳转，防止继续产生未桥接档案。

## 11. 校验、并发和错误处理

- 身份证号非空时不得与另一统一人员主档重复。
- 同一人主要身份时间区间不得重叠。
- 结束日期不得早于开始日期。
- 部门必须属于当前选择的公司或合作单位。
- 项目必须与当前选择的公司或合作单位存在有效关联。
- 班组必须启用且具有施工班组角色。
- 外部施工班组身份必须有班组。
- 内部身份必须有内部子类型；外部身份不得保存内部员工类型。
- 所有编辑和身份切换必须携带并发标记和修改原因。
- 并发冲突返回原页面，保留输入和当前人员分类，并提示刷新后重试。
- 迁移冲突只记录和报告，不静默覆盖或丢弃数据。

## 12. 权限

- 人员查看沿用现有员工查看权限，并纳入施工班组和合作单位页面已有查看范围。
- 人员公共资料、身份切换和内部人员管理：系统管理员、应用管理员。
- 施工班组人员维护：沿用现有施工班组管理权限。
- 合作单位人员维护：沿用现有合作单位管理权限。
- 公司/班组/合作单位部门维护：沿用对应组织的管理权限。
- 身份证、银行卡等敏感字段继续要求敏感人员查看权限，必须服务端脱敏。
- 从统计页跳转不会扩大权限；目标页面再次执行授权过滤。

## 13. 审计

至少记录：

- 人员公共资料修改。
- 当前公司、部门、项目或班组调整。
- 内部转外部、外部转内部。
- 部门新增、编辑、启停。
- 自动创建或重新启用内部员工、班组人员业务档案。
- 迁移自动关联和冲突结果。

审计内容包含操作人、原因、生效日期、修改前后身份及归属，不保存未脱敏敏感信息的页面日志副本。

## 14. 测试与验证

### 14.1 自动化测试

- 领域测试：身份区间、切换规则、当前归属选择和部门所有权。
- 持久化测试：新实体、唯一约束、检查约束、外键和迁移回填。
- 服务测试：人员创建、公共资料同步、内外部切换、班组档案创建、事务回滚和并发冲突。
- 查询测试：公司/班组/合作单位项目与人员统计、精确筛选和点击下钻参数。
- 页面测试：导航改名、内部/外部子入口、黄色框四项控件与联动数据、部门维护、统计链接和旧路由兼容。
- 权限测试：管理入口、只读入口和敏感字段服务端脱敏。
- 导入导出回归：现有员工与班组人员数据仍可读取，统一人员编号和分类不丢失。

### 14.2 界面验证

使用真实登录会话检查：

- 人员详情四项联动选择、取消、保存及刷新后的显示。
- 内部转外部、外部转内部后列表位置、历史和业务入口保持正确。
- 自有公司、施工班组、合作单位部门维护。
- 项目和人员统计卡点击后筛选准确。
- 1440px、1366px 和 390px 下无页面级横向溢出。
- 浏览器控制台、页面脚本和网络请求无错误。

### 14.3 完成门禁

- 相关定向测试全部通过。
- 数据迁移测试通过并能在测试数据库应用。
- 完整 Release 测试通过且无失败、无跳过。
- Release 构建零错误、零警告。
- 浏览器完成桌面和移动端关键流程验证。

## 15. 实施顺序

1. 统一人员主档、身份历史、组织部门所有权和数据库迁移。
2. 统一人员服务及现有员工/班组人员业务档案桥接。
3. 人员管理导航、内部/外部工作台、详情及身份切换。
4. 黄色框四项联动编辑和当前项目计算。
5. 公司、施工班组、合作单位部门维护。
6. 公共组织统计、项目 `BusinessPartnerId` 精确筛选和人员筛选下钻。
