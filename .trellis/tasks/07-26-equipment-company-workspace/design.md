# 设备管理按公司归类与合格证附件改造设计

## 1. 目标与边界

本次改造继续以现有 `Equipment` 为唯一设备主数据，不建立设备管理页私有数据，也不复制项目设备。设备管理与项目施工模块通过同一 `EquipmentId`、应用服务和数据库实体读取设备。

本期只维护每台设备的一份当前有效合格证。替换附件即替换当前文件，不保留历史证书或历史文件版本。现有进退场、租赁协议、维保、权属转让和结算领域保持原有业务边界，仅调整入口和设备基础信息投影。

## 2. 数据模型

### 2.1 管理公司

在 `Equipment` 增加：

- `Guid? ManagingLegalEntityId`
- `LegalEntity? ManagingLegalEntity`

`ManagingLegalEntityId` 表示负责管理、使用或承租该设备的自有公司，是设备总览的唯一公司分类字段。它与权属字段分离：

- 自有设备：必须选择管理公司和产权公司；两者默认相同，但允许不同，以支持集团内代管。
- 租赁设备：必须选择管理公司和出租方；`OwnerLegalEntityId` 为空。
- 新建或编辑设备时，应用服务强制管理公司存在且在操作者可访问的自有公司范围内。

数据库列首期保持可空，用于兼容无法自动判断归属的历史租赁设备；应用层对新增和编辑强制非空。页面将历史空值归入“待分配”，避免给旧数据写入任意公司。

### 2.2 设备基础信息补齐

现有实体已经有但 DTO/表单遗漏的字段纳入统一保存和详情投影：

- `PurchaseDate`
- `PurchaseAmount`

同时保留并完整维护设备编号、名称、型号、分类、权属类型、状态、产权公司、出租方、内部日参考价、备注、并发标记和启用状态。状态不在普通档案弹窗中任意修改，继续由进退场、维保、转让等业务动作驱动。

### 2.3 当前合格证

直接在 `Equipment` 增加：

- `string? QualificationCertificateNumber`
- `DateOnly? QualificationIssuedOn`
- `DateOnly? QualificationExpiresOn`
- `Guid? QualificationAttachmentId`
- `Attachment? QualificationAttachment`

采用一对零或一的当前证书模型，不新增证书历史表。附件复用现有 `Attachment`、`IFileStore` 和证书文件辅助逻辑。外键删除行为使用 `Restrict`，替换或删除附件时先通过文件存储服务处理物理文件，再软删除附件记录并解除设备关联。

校验规则：有效期不得早于发证日期；空附件允许保存证书文本信息；上传时沿用现有证书附件的文件名净化、大小限制、内容类型和授权下载规则。

## 3. 数据迁移与兼容

新增 EF Core migration，并按以下顺序回填 `ManagingLegalEntityId`：

1. 有 `OwnerLegalEntityId` 的设备直接使用产权公司。
2. 无产权公司的设备，使用最近一条设备项目使用记录的 `LegalEntityId`；按进场日期、创建顺序确定最近记录。
3. 仍无法确定的设备保持空值，在工作台“待分配”范围中显示。

迁移不删除、不重命名现有权属字段，也不改变已有项目、进退场、租赁和结算记录。回滚 migration 时仅移除本次新增列、索引和外键，不触碰共享附件表中的其他业务附件。

## 4. 应用服务与共享契约

扩展 `SaveEquipmentRequest` 与 `EquipmentDetailsDto`，加入管理公司、管理公司名称、产权公司名称、出租方名称、采购字段、当前合格证元数据和附件摘要。附件上传使用独立的上传值对象，避免 Web 层类型进入应用层。

`IEquipmentService` 增加：

- 按 ID 获取设备详情，避免编辑弹窗通过全量 dashboard 查找单条记录。
- 保存设备时同时处理当前合格证文本和附件替换/删除。
- 授权下载当前设备合格证附件。
- 工作台查询返回公司汇总与设备列表所需投影。

`EquipmentFilter.CompanyId` 仅按 `ManagingLegalEntityId` 分类过滤，不再混入项目使用公司的隐式条件；项目筛选继续使用 `ProjectId`。授权查询也加入管理公司，使租赁设备不再依赖项目使用记录才能被公司用户访问，同时保留现有产权公司与项目访问兼容逻辑。

项目施工模块继续调用 `IEquipmentService.SaveEquipmentAsync`。项目侧新增设备请求同步增加管理公司以及补齐的基础字段；已有设备选择列表显示“设备编号 · 名称 · 管理公司 · 自有/租赁”，让项目人员读取到设备管理维护的数据。

## 5. 设备工作台页面

设备首页参考自有公司工作台，但保持设备业务密度：

- 顶部：标题、当前范围摘要、新增设备、现场离线记录。
- 公司筛选：支持“全部公司”、每个可访问自有公司和“待分配”。筛选使用查询参数，可刷新、复制链接和后退恢复。
- 左侧：当前范围的设备总数、使用中、闲置、租赁、证书临期/过期数量及状态分布。
- 右侧：紧凑设备表格，核心列为编号/名称、型号分类、管理公司、权属、状态、合格证、当前项目或使用状态、操作。
- 在常见桌面宽度优先压缩次要列和采用两行单元格，不要求用户横向拖动才能完成主要操作；窄屏允许表格容器滚动。

设备名称不再跳转详情页，点击名称或“查看”均打开只读详情弹窗。

## 6. 弹窗交互

首页提供以下原生 `<dialog>` 工作流：

- 新增设备
- 查看设备
- 编辑设备
- 复制设备
- 进退场维护

详情弹窗内可继续进入维保、权属转让等既有设备操作；若这些操作出现在右侧列表中，也必须打开弹窗，不使用页面导航。现场离线记录属于独立现场工作流，保留页面入口。

弹窗内容通过 Razor 局部视图复用。GET handler 返回表单所需数据或局部 HTML；POST handler 使用同一 PageModel 完成校验和保存。保存成功后返回当前工作台筛选地址并显示成功提示；校验失败时原弹窗保持打开并展示字段错误。打开和关闭弹窗不改变页面布局，也不嵌套卡片。

新增/编辑表单分为设备识别、公司与权属、采购与计价、当前合格证、备注与修改原因五组。权属切换时：

- 自有：显示产权公司，隐藏并清空出租方。
- 租赁：显示出租方，隐藏并清空产权公司。
- 管理公司始终显示，数据源为当前用户可访问的自有公司。

## 7. 附件流程与安全

Web 层接收 `IFormFile` 后转换为应用层上传对象。服务在保存前验证安全文件名、非空内容、允许大小和内容类型；下载 handler 先执行设备可见性授权，再从 `IFileStore` 读取并返回原始文件名和内容类型。

替换流程先保存新文件并建立新附件，再在事务成功路径解除旧关联和删除旧文件；如果数据库保存失败，应清理新文件，避免孤立文件。删除附件只移除附件，不清空证书编号和日期。所有附件变更进入设备审计快照和修改原因。

## 8. 错误与并发处理

- 使用现有 `ConcurrencyStamp` 防止覆盖他人修改。
- 公司、产权方或出租方不存在/停用/无权访问时返回明确字段级或业务错误。
- 历史待分配设备可查看，但首次编辑保存时必须选择管理公司。
- 附件下载不存在或无权访问时返回现有统一的 404/授权处理，不暴露存储路径。
- 弹窗 POST 失败时恢复公司和出租方下拉选项，并保持用户已输入内容。

## 9. 测试与验收

### 领域与基础设施

- 新增/编辑时管理公司校验。
- 自有与租赁字段互斥规则。
- 采购字段和证书元数据完整保存、读取与复制行为。
- 合格证上传、替换、删除、下载和无权访问。
- dashboard 全部公司、指定公司、待分配筛选及授权范围。
- migration 模型快照、回填 SQL 和回滚结构。

### Web

- 首页输出公司筛选、左右工作台和紧凑列表。
- 新增、查看、编辑、复制、进退场入口均为 dialog 触发器，无对应页面跳转链接。
- 无效提交保持目标弹窗打开并恢复选项。
- 权属切换控制正确，文件表单使用 `multipart/form-data`。
- 项目设备选项读取管理公司与权属信息，项目内新增设备使用统一保存契约。

### 浏览器验收

在桌面和移动视口验证：公司切换、列表密度、弹窗开关、表单条件字段、附件操作、保存后筛选保持、项目页设备读取，以及无重叠和主要操作无需桌面横向滚动。
