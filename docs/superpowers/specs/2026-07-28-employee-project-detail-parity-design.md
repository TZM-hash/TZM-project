# 员工详情与项目详情体验对齐设计

## 目标

将员工详情页改造为与项目详情页一致的单页工作台：顶部展示员工身份与年度经营指标，中部展示可快捷编辑的基础资料，下部通过横向标签切换员工业务明细，右侧固定展示提示与修改记录。员工列表的“编辑”直接进入详情并自动开启快捷编辑，“查看”弹窗扩展为完整只读概览。

## 范围与边界

- 改造员工列表的查看、编辑和复制入口。
- 改造员工详情的标题、指标卡、基础资料、横向标签和右侧动态栏。
- 扩展查看弹窗中的员工基本资料、归属、默认计薪和年度汇总信息。
- 保留现有工资、报销、其他应付、付款、证书、年度结转、权限和审计规则。
- 不修改数据库结构，不新增重复财务记录，不改变工资台账和中央账本的唯一编辑源。

## 员工列表操作

### 查看

“查看”继续打开只读弹窗。弹窗按项目详情的分组卡片展示：

- 人员资料：员工编号、姓名、员工类型、状态、岗位、电话、入职日期和离职日期。
- 当前归属：公司、部门、项目、班组和归属岗位。
- 敏感资料：身份证、银行卡和开户行；服务端继续按权限返回原值或脱敏值。
- 默认计薪：月薪、日薪、时薪和计件单价。
- 当前年度汇总：往年结转、工资应付、罚款扣减、报销应付、其他应付、本年新增应付、已付款、当前余额和结算进度。
- 风险提示：负余额、超付和关键资料缺失。

弹窗底部为“关闭”“进入完整档案”和有权限时的“编辑员工”。

### 编辑

“编辑”不再打开主档编辑弹窗，改为跳转员工详情并携带 `edit=profile`。详情页加载后自动开启基础资料快捷编辑，焦点落在第一个可编辑字段。无编辑权限时忽略该参数并保持只读。

### 复制

“复制”继续复用现有复制规则，清空员工编号、电话、身份证、银行卡、开户行和入离职日期等不应继承的唯一或个人字段。复制成功后进入新员工详情页，便于继续完善资料。

## 员工详情总体结构

页面结构与项目详情保持一致：

```text
返回上级
员工标题与右侧操作
年度指标卡
基础资料与当前归属快捷编辑
关联概览卡
横向业务标签 + 当前标签内容
右侧提示与修改记录
```

桌面端主内容与动态栏并排，动态栏独立滚动；窄屏下动态栏移动到业务内容之后。

## 标题与年度指标

标题区展示员工编号、姓名、员工类型、岗位、当前公司和部门；右侧展示启用状态、复制和其他已授权操作。业务年度选择继续控制年度汇总与年度业务明细。

年度指标卡包括：

1. 往年结转。
2. 工资应付。
3. 罚款扣减。
4. 报销应付。
5. 利息分红及其他应付。
6. 本年新增应付。
7. 已付款。
8. 当前余额 / 未付款。

罚款扣减来源于工资明细中的 `EmployeeWageEntryType.Penalty`，以正数录入、在工资应付中按负向金额计算。指标卡仅单独解释其影响，不创建第二份扣款或再次从总额中扣除。

## 基础资料与快捷编辑

基础资料面板复用项目详情的卡片网格、原位输入和操作区，分为：

- 人员资料：编号、姓名、类型、状态、岗位、电话、入离职日期。
- 敏感资料：身份证、银行卡、开户行。
- 默认计薪：月薪、日薪、时薪、计件单价。
- 当前归属：公司、部门、项目、班组、归属岗位和生效日期。

点击“快捷编辑”后，允许编辑的显示值在原位置切换为输入控件；保存和取消按钮替代“快捷编辑”。保存携带修改原因和并发标记。复杂的历史归属变更不在快捷编辑中重写，继续使用专门的归属维护流程。

当页面带有 `edit=profile` 且用户有员工管理权限时，自动进入快捷编辑状态。校验失败或并发冲突时保留编辑状态、输入值、当前业务年度和当前标签。

## 横向业务标签

详情下半部分使用与项目详情一致的横向标签，每次仅展开一个业务区：

1. 工资明细：二级标签为全部、考勤工资、加班工资、奖金、罚款和其他。
2. 报销明细。
3. 利息分红及其他应付。
4. 付款记录：只读追溯工资台账来源，不提供新增、编辑或删除。
5. 证书管理。

每个标签复用项目详情的标题、说明、快捷编辑、新增折叠区、表格、附件和备注交互。URL 参数继续保存当前标签和二级标签，刷新及错误返回后不丢失位置。

## 右侧提示与记录

动态栏参考项目详情的“提示与记录”，统一展示：

- 员工主档与归属修改记录。
- 工资、罚款、报销及其他应付变化。
- 工资批次付款和冲销记录。
- 证书新增、修改和到期提醒。
- 负余额、超付、资料缺失和来源失效等风险提示。

现有数据能够直接生成的记录优先展示；没有可靠审计来源的内容不伪造时间或操作人。

## 计算口径

年度总账继续使用现有计算器：

```text
本年新增应付 = 工资应付 + 报销应付 + 其他应付 + 调整金额
当前余额 = 往年结转 + 本年新增应付 - 已付款
结算进度 = 已付款 /（往年结转 + 本年新增应付）
```

- 工资应付由考勤工资、加班工资、奖金、罚款和其他工资记录汇总。
- 报销应付单独汇总。
- 分红、利息及其他应付归入其他应付。
- 调整金额保留在年度总账口径中；没有独立业务明细时只在汇总或动态中解释，不伪装成工资、报销或其他应付。
- 已付款只读取工资台账分配和既有付款来源，不在员工详情重复保存。

## 权限和敏感信息

- 查询角色可查看授权范围内的员工详情和脱敏信息。
- 系统管理员、应用管理员可编辑员工主档和复制员工。
- 财务权限继续控制工资、报销、其他应付和付款信息。
- 无敏感信息权限时，身份证和银行卡必须在服务端脱敏，前端数据载荷不得包含原值。

## 错误处理与兼容

- 旧的员工详情地址、业务年度、标签及二级标签参数继续有效。
- 原独立新增/编辑地址保留为兼容入口，但列表编辑主路径切换到详情快捷编辑。
- 保存失败、并发冲突和权限拒绝继续使用现有服务端语义。
- JavaScript 不可用时，详情页仍显示只读资料，编辑入口可回退到兼容编辑页。

## 验证

- 页面模型测试：`edit=profile` 权限控制、年度选择、标签保持、快捷编辑保存和并发错误。
- 页面契约测试：项目式标题、八项指标、基础资料面板、横向标签和右侧动态栏。
- 查看弹窗测试：基本资料、归属、默认计薪、年度汇总、风险、脱敏和跳转链接。
- 计算测试：罚款只扣减一次，年度新增应付、当前余额和结算进度沿用现有公式。
- 回归测试：工资、报销、其他应付、付款来源、证书和员工年度总账。
- Release 构建和桌面端页面检查。

## 验收标准

1. 员工详情的布局、快捷编辑、横向标签和右侧动态与项目详情保持一致。
2. 列表“编辑”进入员工详情并自动开启快捷编辑。
3. 查看弹窗完整展示授权范围内的基本资料和年度汇总信息。
4. 罚款、工资、报销、其他应付、调整和付款不重复计算。
5. 现有权限、脱敏、深链接、工资台账和中央账本关系不退化。
