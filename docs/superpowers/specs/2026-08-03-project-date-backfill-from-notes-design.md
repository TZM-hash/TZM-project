# 项目备注日期回填设计

## 目标

从项目备注中的机器进场、退场和完工记录补齐项目的实际开工日期与实际完工日期，优先恢复可确认的历史数据，同时把无法安全判断的记录留给人工核实。

## 规则

1. 只解析包含完整年份的日期：`2025.3.10`、`2025年3月10日`、`2025/3/10`、`2025-3-10`、`20250310` 和 `202012.1` 等格式。
2. 日期必须位于机器/设备/租赁等工程上下文中，或与明确的生命周期词相邻。
3. 付款、收款、转账、发票、税金、保证金、工资等财务上下文中的日期不参与项目日期推导。
4. 最早的进场/入场/到场/进驻/开始施工日期作为实际开工候选；最晚的退场/撤场/退租/出场/完工/结束/转让日期作为实际完工候选。
5. 无年份、格式异常、只记录进场而没有完工事件、或完工早于开工的记录不猜测写入，只进入 JSON 报告的待核实列表。
6. 仅补齐空的 `ActualStartDate` / `ActualCompletionDate`，已有值视为人工确认，不覆盖。

## 实现边界

- 新增独立的 `ProjectNoteDateParser` 与 `ProjectDateBackfillService`，不把备注解析混入项目查询或页面逻辑。
- 增加 `--backfill-project-dates-from-notes` 维护模式。命令先调用既有 SQL Server 备份执行器，再在单个事务中回填，并写入 `App_Data/logs` JSON 报告和 `AuditLogs`。
- 报告包含每个项目的候选日期、来源片段、跳过原因和实际变更映射，重复执行应产生零变更。
- 不新增数据库字段、不改变项目编号、状态或关系；失败时事务回滚，备份保留。

## 验证

- 解析器单元测试覆盖多种日期格式、财务日期排除、无年份日期、进场/完工候选和异常顺序。
- 回填服务测试覆盖只填空字段、已有日期不覆盖、事务结果和幂等。
- 运行全量测试、Release 构建、SQL Server 维护命令和回填前后只读审计。
