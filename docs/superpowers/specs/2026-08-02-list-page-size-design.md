# 全局列表分页条数设计

## 目标

让系统中每个可见列表独立支持自定义每页显示条数，统一提供 20、50、100 三个选项；项目、员工、财务兼容页和中央账本等已有服务端分页页面继续使用服务端查询，其余完整渲染的列表使用共享客户端分页。

## 范围与边界

- 覆盖所有可见 `table.data-table`，包括 DataWorkbench 主列表、详情页子列表、弹窗内列表和无 DataWorkbench 的小页面。
- 排除 `sr-only` 图表辅助表、明确标记 `data-list-pagination-disabled` 的表和空表。
- 每个表格拥有独立的条数、页码和分页导航；同一页面的其他表格不受切换影响。
- 默认每页 20 条；非法或缺失值回退到 20；只接受 20、50、100。
- 切换条数或页码保留当前搜索、筛选、排序和其他 URL 查询参数；页码变化只更新对应列表的状态。
- 服务器分页页面的现有 PageSize、PageNumber 和分页链接继续作为事实来源；共享脚本不重复切分服务端已经返回的一页数据。

## 方案

### 共享分页模块

新增 `wwwroot/js/components/list-pagination.js`，扫描可见数据表并为每个表建立独立状态：

- 识别表格所属 DataWorkbench；优先复用工作台已有的 `[data-current-page-size]` 选择器。
- 无工作台的表格在表格上方生成条数选择器和分页导航。
- 客户端表格按业务行切分，合计、空状态和 `[data-pagination-fixed]` 行始终保留在表尾。
- 监听 MutationObserver，动态增删行后重新计算总页数并修正当前页。
- 以 `engineering-manager-list-pagination:<scope>:<table-id>` 保存客户端条数和页码；URL 中存在 `pageSize` 或 `page` 时优先使用 URL 值。

### DataWorkbench 接入

- 所有预设将 `CanChangePageSize` 打开，沿用现有的 20/50/100 选择器。
- 工作台根节点声明客户端或服务端分页模式；服务端模式由页面模型继续处理查询，客户端模式由共享分页模块切分 DOM 行。
- 工作台条数改变时清除对应页码并保留其他查询参数；服务端模式导航到页面 URL，客户端模式刷新列表状态而不破坏筛选。

### 独立服务端页面

- 项目、员工、财务兼容页和两个中央账本保留现有 PageSize 绑定、合法值归一化及 PageUrl/TabUrl 参数。
- 统一在这些页面的分页区域呈现当前条数和条数选择器；排序切换继续清除页码并保持条数。
- 对已有服务端分页页面增加契约测试，保证页面包含 20/50/100 选项并将选择传入查询。

## 交互与可访问性

- 条数选择器使用 `label` 与 `aria-label="每页显示条数"`；分页导航使用 `nav` 和页面语义标签。
- 条数变更将页码重置为 1；当前页超出总页数时自动回退到最后一页。
- 单页或空表隐藏分页导航，但保留条数选择器的统一位置，避免工具栏跳动。
- 移动端沿用现有工具栏换行和表格横向滚动样式，不新增固定宽度。

## 数据流与错误处理

1. Razor 输出完整表格、当前服务端状态和分页模式。
2. 共享脚本读取 URL、工作台属性和本地状态，验证条数后初始化表格。
3. 服务端分页表格只显示服务端返回的行；客户端分页表格只切换行的 `hidden` 状态。
4. 任何非法条数、负页码、缺少表格 ID 或 localStorage 不可用时使用安全默认值，不阻断页面其它脚本。

## 测试策略

- JavaScript 资产契约测试：扫描规则、20/50/100 选项、客户端/服务端分支、独立 key、动态行重算和 URL 参数保留。
- Razor 页面契约测试：DataWorkbench 预设开启条数选择；服务端分页页仍绑定 PageSize 并保留排序与筛选参数。
- 服务端模型测试：20/50/100 正常传递，非法值归一化为 20，分页查询按所选条数返回。
- 回归运行 Web 定向测试、完整 `dotnet test` 和 Release 构建。

## 风险与取舍

- 客户端列表仍会加载完整结果，适合当前页面架构且改动小；未来若单表数据量显著增长，可把同一数据属性迁移到服务端分页而不改变交互契约。
- 详情页多个列表分别分页会增加少量工具栏元素，但能避免一个列表的设置影响另一个列表，符合用户要求。
