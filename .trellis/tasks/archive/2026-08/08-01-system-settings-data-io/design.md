# 技术设计：系统设置与数据导入导出完善

## 范围与边界

本任务沿用现有 Razor Pages、Application DTO/service、Infrastructure EF Core 和中央账本模型，不新增独立服务或替换数据库架构。改动分为五个边界：设置与前端壳层、财务汇总查询、员工 Excel 补导、中文化/编号策略、数据交换模板。现有未提交的中央账本计算器改动不重写；若总览需要公共计算逻辑，只通过现有服务接口复用。

## 设置与页面壳层

`GlobalFontSize` 存储为受限字符串枚举（小/标准/大/特大），默认标准，对应当前根字号 15px。系统设置服务负责规范化、持久化、缓存失效和审计；布局把字号 class 放到 `<html>`，CSS 以 `rem`/根变量统一放大，设置页提供预览。`site.js` 改为同步完成导航和轻量交互，重型模块进入 `requestIdleCallback` 队列；导航增加可取消的轻量 pending 状态，避免重复初始化。Apple 动效只缩短页面进入动画，不改变用户偏好存储。

## 项目财务汇总

项目列表先一次性读取项目级结算、现金、发票及必要的员工/设备聚合，按项目在内存中合并，避免 `ListProjectSummariesAsync` 对每个项目调用 `GetProjectSummaryAsync`。现金和发票分别按直接 `ProjectId` 与分摊记录去重/合并；没有分摊的项目级记录也纳入。比率沿用现有 DTO 语义：收款/应收、开票/应收、付款/应付；分母为零时返回 0，避免 NaN。详情查询保留完整明细能力，但列表不再加载全部审计和中央账本明细。

## 员工 Excel 导入

以“员工总表”为工资主来源，以其他工作表为已付款/往来补充来源。建立或获取 2026 业务年度；员工通过稳定的员工编号优先、姓名+身份证/银行卡其次匹配。每一类结果写入现有 `EmployeeWageEntry`、`EmployeeReceipt`、`EmployeeFinancialAdjustment` 或已有工资批次模型，携带来源文件、工作表和行号。导入器先预览并输出逐行错误，正式模式在单事务中执行；业务键保证幂等。导入后用现有年度台账服务重新计算应发/已发/未发，并把公式结果写成校验报告。

## 中文化与编号

增加集中枚举/状态显示映射，导出和 Razor 页面禁止直接使用面向用户的 `.ToString()`。对于不能立即迁移的旧值，输入端接受中英文兼容别名，输出端只输出中文。自动编号策略只应用于新建记录，通过短前缀、年月日和短序号/短随机尾段保证范围内唯一；历史值保留，查询同时支持历史和新值。

## 导入导出契约

统一模板约定：第一行中文列名，第二行可选示例/说明，日期为 `yyyy-MM-dd`，金额为两位小数，枚举为中文显示值，关联使用“编号”和“名称”两列，错误报告包含行号、字段、原因和建议。中央账本导出直接读取 `FinanceSettlements`、`FinanceCashEntries`、`FinanceInvoices` 及分摊关系；旧表只作为兼容导入来源。每种模板提供列定义和空模板，导出字段与导入解析共用映射，保证回读。

## 风险与回滚

- 旧数据字段语义不一致：先预览、按来源行落审计/报告，不自动覆盖已有非空值。
- 项目汇总口径变化：以现有详情 DTO 测试作为基准，增加无分摊项目回归样例。
- 前端延迟初始化遗漏模块：保留页面 data attribute 作为显式注册点，并在 Web 测试中检查关键模块先后。
- 导入失败：事务回滚业务写入，保留预览报告；不删除已有记录。

## 验证策略

先为每个行为新增失败测试并单独运行确认失败，再实现最小改动。完成后运行相关 xUnit 测试、Web 测试、性能代表性测试、完整 `dotnet test`、无共享编译器构建，并使用测试库查询核对员工和项目汇总。
